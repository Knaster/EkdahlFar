\begin{DoxyItemize}
\item actuator -\/ the object that is physically rotated against the string, usually a replaceable felt disc.
\item soft-\/limit -\/ a stored value above or below which a certain physical movement or action will not be taken, e.\+g. minimum motor speed or maximum bow pressure
\item command message -\/ a text-\/based message with none or more arguments, all external control of the software is done through these messages
\item bowing jack -\/ the assembly that holds the DC bowing motor and reflection sensor tachometer

The Ekdahl FAR is structured around a hierarchal concept of \doxylink{classModule}{modules} that handles specific parts of the instrument, whether internal or external, software or hardware related. All {\itshape modules} have a \doxylink{structModuleCommandDeclaration}{module command declaration} which shows what {\itshape commands} the module has and some basic information about the {\itshape commands}. This information is used both internally to call the associated functions as well as offering an interface for users or connected software to discover the capabilities of each {\itshape module}.

The subclass \doxylink{classModuleHandler}{module handler} allows a module to contain other modules using \doxylink{classModuleGroup}{module groups}. Each {\itshape module} {\itshape group} can contain any number of instances of single type of \doxylink{classModule}{Module} or \doxylink{classModuleHandler}{module handler} class. Addressing of {\itshape modules} is done in a hierarchal manner using the full names of all preceding modules separated with a \textquotesingle{}.\textquotesingle{}. Individual children of {\itshape module} {\itshape groups} are optionally addressed using {\itshape indexing} through brackets \textquotesingle{}\mbox{[}\mbox{]}\textquotesingle{} and accepts both singles (\textquotesingle{}\mbox{[}2\mbox{]}\textquotesingle{}), ranges (\textquotesingle{}\mbox{[}0-\/2\mbox{]}\textquotesingle{}) and comma separated instances (\textquotesingle{}\mbox{[}0-\/1,3\mbox{]}\textquotesingle{}).

Addressing a child with an {\itshape index} but without calling a {\itshape command} in that child creates a {\itshape selection}, these {\itshape selections} are used by owning {\itshape modules} in order to do things like changing MIDI configuration or harmonic table. A {\itshape selection} can also be used by later {\itshape commands} in order to invoke functions on the currently selected child by omitting the brackets when addressing. If omitting the brackets and there is no previous selection, the first (\mbox{[}0\mbox{]}) child is addressed.

The main \doxylink{main_8cpp_afe461d27b9c48d5921c00d521181f12f}{loop} function periodically runs basic function calls which are not time-\/sensitive while time-\/critical functions are called through periodic interrupts. All messages are processed by their respective {\itshape modules} with the \doxylink{classMasterModule}{master module} offering a few system functions, the root {\itshape module} {\itshape handler} passed when creating the {\itshape master} {\itshape module} contains commands specific to the current setup. Certain {\itshape commands} are offered by ALL modules and are declared in \doxylink{classModule_a2b930f376b031611ccdf0070585fb805}{Module\+::builtin\+Commands}, as of this writing these are\+: ~\newline
 ~\newline
list -\/ returns all {\itshape commands} and child {\itshape modules} within the {\itshape module} ~\newline
help -\/ returns detailed information about each child {\itshape module} and {\itshape command}, for use both by direct users and software ~\newline
dump -\/ returns all data currently associated with each {\itshape command} and child {\itshape module}, used by software and internally to store parameters ~\newline
 ~\newline
 All {\itshape commands} can be invoked through USB-\/\+Serial, RS232 and added to queue by internal functions that may or may not be connected to other external hardware. All incoming MIDI-\/messages are mapped to a editable string of {\itshape command} messages, this way complete freedom in midi-\/mapping is obtained. A universal messaging system that is ignorant of the source of the {\itshape command} messages makes for a more transparent and uniform way of handling events, hardware control and data processing. This also makes for a system where minimal code changes are required when doing modifications or introducing new functionality and options.
